# 開發指南

## 環境

推薦使用 [`uv`](https://docs.astral.sh/uv/)。`scripts/gen_workflow_docs.py` 內含 [PEP 723](https://peps.python.org/pep-0723/) inline metadata，`uv run` 會自動建立隔離環境並安裝相依，不需手動建 venv：

```bash
uv run scripts/gen_workflow_docs.py
```

若無 `uv`，可改用：

```bash
pip install pyyaml
python scripts/gen_workflow_docs.py
```

## 新增 / 修改 workflow

1. 編輯或建立 `.github/workflows/<Name>.yml`
2. 於檔案最開頭加上 metadata comment（兩行皆必要）：

   ```yaml
   # summary: 一句話描述
   # category: 分類名稱
   name: ...
   on:
     workflow_call:
       ...
   ```

3. 重新產生文件與 README 索引：

   ```bash
   uv run scripts/gen_workflow_docs.py
   ```

4. 提交 `.github/workflows/`、`docs/`、`README.md` 的全部變更

## CI 檢查

```bash
uv run scripts/gen_workflow_docs.py --check
```

`docs/` 或 `README.md` 與 workflow 定義不同步時 exit 1。CI workflow `_docs-check.yml` 會於 PR 自動執行。

## 慣例

- **檔名**：以 `_` 開頭的 workflow 為內部 CI，產生器會跳過、不出現在索引（如 `_docs-check.yml`）
- **docs/**：自動產生的 `.md` 開頭含 `<!-- generated by ... -->` marker；產生器只會刪除帶此 marker 的檔案，手寫文件可安心放在同目錄
- **Symlink**：GitHub Actions 不可靠地跟隨 `.github/workflows/` 內的 symlink，因此 yml 與 docs 採分離 + 產生器同步的方式維護
